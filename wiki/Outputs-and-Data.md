# Outputs, formats, and terminology

## Output locations

The default scenario output folders are:

- Central-area map: `centar/scenario-output/`
- Skopje and Skopje Lite: `skopje/scenario-output/`

`--output-dir` can change the folder. A relative path is resolved below the
directory for the selected map. Comparison output is rooted below the Skopje
directory and split by map.

Generated files include:

| File | Purpose |
|---|---|
| `passenger.trips.xml` | Passenger trip definitions from SUMO `randomTrips.py`. |
| `passenger.rou.xml` | Validated passenger vehicles and routes used in the run. |
| `ambulance.rou.xml` | Generated emergency ambulance vehicle/route on Skopje maps. Central-area runs use the tracked preconfigured `centar/amb.rou.xml`. |
| `tripinfo.xml` | SUMO trip-level departure, arrival, duration, and related information. |
| `ambulance-route-N.pdf` | Network map with the ambulance's recorded traversed roads highlighted in red and run/search parameters. `N` increments to avoid overwriting. |
| `runtime-comparison.pdf` | Whole-run and ambulance trip-time comparison produced by `--compare-time`. |
| `training-report.pdf` | Training objective plot and parameter summary. |
| `training-results.csv` | Tabular row per training evaluation. |
| `training-results.json` | Detailed training metadata, evaluations, and artifact paths. |
| `training-best-<profile-id>.json` | Best completed training result for a specific matching scenario profile. |
| `evaluation-NNN/` | Per-evaluation scenario output generated by training. |

Generated scenario folders are ignored by Git. Avoid editing generated XML
while its simulation is running.

## Search-default JSON keywords

`centar/search_defaults.json` is a JSON object with these keys:

| Key | Type/range | Meaning |
|---|---|---|
| `search_algorithm` | `"dijkstra"` or `"astar"` | Default route-search algorithm. |
| `replan_interval` | finite number `> 0` | Simulation seconds between route recalculations. |
| `traffic_light_penalty` | `null` or finite number `>= 0` | Added estimated seconds for a route edge ending at a traffic-light node. `null` asks the controller to select a mode-dependent value. |
| `astar_heuristic_weight` | finite number `>= 0` | A* straight-line travel-time heuristic multiplier. Values over `1` can sacrifice optimality. |

Both scenario runner and direct controller validate this file at startup.
Training writes it only after at least one completed trip, unless
`--no-apply` is passed. Writes use temporary-file replacement.

Example:

```json
{
  "search_algorithm": "dijkstra",
  "replan_interval": 30.0,
  "traffic_light_penalty": 0.0,
  "astar_heuristic_weight": 1.0
}
```

## SUMO XML vocabulary used here

SUMO route files are XML. The project creates or reads these elements and
attributes:

| Element/attribute | Meaning in this project |
|---|---|
| `<routes>` | Root element for vehicle types and trip/vehicle definitions. |
| `<vType id="amb" ...>` | Declares the ambulance's vehicle type. `vClass="emergency"` selects emergency-vehicle access; `guiShape` and `color` affect the GUI. `speedFactor="1.3"` is used in the generated type. |
| `<param key="has.bluelight.device" value="true"/>` | SUMO vehicle parameter declaring the blue-light device. |
| `<trip ...>` | SUMO trip definition with `id`, `type`, `depart`, `from`, and `to`; SUMO can calculate its route. Used by the central-area route. |
| `<vehicle ...>` | Explicit vehicle definition; generated ambulance includes `id="amb0"`, `type="amb"`, and `depart`. |
| `<route edges="..."/>` | Ordered, space-separated road edge IDs used by the vehicle. Generated ambulance has an explicit route. |
| `<stop lane="..." endPos="..." duration="..."/>` | Temporary stop appended to a passenger vehicle to model a blockage. |
| `depart` | Simulation time in seconds when a vehicle starts. |
| `duration` | Trip duration (in tripinfo) or stop duration, depending on context. |
| `edges` | Ordered SUMO network edge IDs in a route. |
| `vClass` | Vehicle access class checked against network edges and lanes. |
| `<tripinfo id="amb0" duration="..."/>` | SUMO output record used by training and comparison to measure ambulance trip completion and duration. |

SUMO simulation times and trip durations are in simulation seconds. Wall-clock
times in route/comparison reports are real elapsed seconds. The route PDF's
initial Dijkstra ETA is an estimated cost; the tripinfo duration is the
measured simulation result.

## Glossary

- **Edge:** A directed road segment in a SUMO network.
- **Lane:** A travel lane belonging to an edge; lane access may differ by
  vehicle class.
- **Emergency-accessible:** The edge/lane allows SUMO's `emergency` class.
- **TraCI:** SUMO's Traffic Control Interface, used to read/update simulation
  state while SUMO runs.
- **Replanning:** Recompute a path from the ambulance's current edge to the
  original destination using current estimated edge costs.
- **Signal preemption:** Temporarily request/extend a green for the ambulance
  at a nearby traffic light.
- **Penalty:** A configurable estimated route cost; it does not represent a
  physical waiting-time measurement.
- **SPSA:** Simultaneous perturbation stochastic approximation, a
  finite-difference method estimating a search direction from two perturbed
  objective measurements per iteration.
- **Objective:** The measured ambulance trip duration used to compare training
  evaluations.
- **Skopje Lite:** The smaller network at `skopje/skopjelite.net.xml` used by
  the training program for quicker repeated evaluations.
